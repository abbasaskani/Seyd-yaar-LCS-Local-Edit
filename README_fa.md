# صیدیار LCS — نسخه توسعه‌یافته با نقشه تعاملی

این پروژه «ساختارهای لاگرانژی جاذب (Attracting FTLE)» را از میدان جریان مدل Copernicus استخراج می‌کند. **خروجی شاخص تجمع بالقوه به معنی احتمال تأییدشده صید ماهی تن نیست.**

## مهم‌ترین تغییرات

- اجرای روتین برای ۱۴ روز گذشته، امروز و تا ۱۰ روز آینده (در مجموع حداکثر ۲۵ خروجی روزانه).
- آیندهٔ واقعی از تاریخ/ساعت موجود در داده تعیین می‌شود. تاریخ‌های فاقد پوشش FTLE کامل با علت در `outputs/latest/run_report.json` ثبت و حذف می‌شوند. تنها وقتی هیچ روزی قابل پردازش نباشد اجرای کل job ناموفق اعلام می‌شود.
- برای روز `-14` و `backward_days=7` از داده‌های `-21` تا `-14` استفاده می‌شود؛ برای روزهای آینده نیز به ۷ روز **قبل از همان روز هدف** رجوع می‌شود.
- دانلود یک‌باره پنجرهٔ زمانی مشترک، با تلاش مجدد برای افق‌های کوتاه‌تر در صورت عدم موجودی آینده.
- ورود دستی چهار مختصات در GitHub Actions **پیش از Run**: `lon_min/lon_max/lat_min/lat_max`. چهار کادر باید همگی خالی یا همگی پُر باشند؛ خالی یعنی استفاده از GeoJSON پیش‌فرض.
- افزودن بافر فضایی ۱ درجه اطراف محدوده برای کاهش آثار لبه؛ فقط AOI درخواست‌شده در نتایج نمایش داده می‌شود.
- توقف و حذف مسیرهای برخوردکننده با خشکی مدل، و ماسک محافظه‌کارانه در حاشیهٔ خشکی؛ جلوگیری از رسم خطوط از بین خشکی و جزیره. تفکیک ساحلی با تفکیک Copernicus محدود است؛ جزایر خیلی کوچک قابل ضمانت نیستند.
- داشبورد `docs/latest/index.html` با نقشهٔ واقعی OpenStreetMap/Leaflet، خطوط برداری GeoJSON، نقاط داغ، خوشه‌ها، لایه سرعت و پاپ‌آپ در هر سلول دریایی.
- ویدیوی MP4 تغییر **نقشه‌های روزانه شاخص تجمع**؛ این ویدیو انیمیشن فیزیکی جریان آب یا ردیابی واقعی ماهی نیست.
- کنترل نکردن دستی آفستِ پروژه مرجع؛ مختصات مستقیماً از محورهای NetCDF خوانده می‌شود.

## شروع روی GitHub

1. تمام محتویات پوشه پروژه را به ریشه مخزن GitHub منتقل کن. در Settings > Secrets and variables > Actions این دو secret را داشته باش: `COPERNICUSMARINE_SERVICE_USERNAME` و `COPERNICUSMARINE_SERVICE_PASSWORD`.
2. به `Actions` → `Run Seyd Yar LCS` → `Run workflow` برو.
3. `mode_choice=routine` انتخاب کن. اگر می‌خواهی محدوده سفارشی بدهی، هر چهار عدد `lon_min/lon_max/lat_min/lat_max` را با **درجه اعشاری WGS84** پر کن. نمونه: `60.2, 65.7, 16.4, 23.5`. در صورت خالی بودن، `config/aoi/current.geojson` استفاده می‌شود.
4. منتظر اتمام اجرای GitHub Actions باش. خروجی‌های قابل دانلود در artifact به نام `seyd-yaar-lcs-outputs` قرار می‌گیرند. داشبورد هم از GitHub Pages منتشر می‌شود (باید Pages/Actions برای مخزن مجاز باشد).

## ساختار فایل‌ها

| فایل | کاربرد |
|---|---|
| `config/defaults.json` | افق روزانه `-14..+10`، ۷ روز backward FTLE، بافر و تنظیم ساحل |
| `scripts/run_scheduled_modes.py` | دانلود مشترک، تلاش تطبیقی، پردازش روزانه، ثبت روزهای ردشده |
| `scripts/run_pipeline.py` | محاسبهٔ یک روز از دادهٔ مشترک/دریافتی |
| `lcs_pipeline/land.py` | کنترل عبور مسیرهای ذرات از سلول خشکی |
| `lcs_pipeline/availability.py` | سنجش پوشش زمانی و مدیریت خطاهای بازه داده |
| `scripts/build_pages.py` | تولید لایه‌ها، صفحات، و ویدیوی تحول روزانه |
| `docs/lcs_template.html` و `docs/lcs_app.js` | فرانت‌اند تعاملی |
| `outputs/latest/run_report.json` | علت موفقیت/حذف هر روز |

## توضیحات فنی و محدودیت‌ها

- محصول `GLOBAL_ANALYSISFORECAST_PHY_001_024` و دیتاست ساعتی `cmems_mod_glo_phy_anfc_merged-uv_PT1H-i` برای متغیرهای `uo/vo` استفاده می‌شوند. با پایان‌یافتن زمان‌های واقعی مدل، نتیجهٔ آن روز Skip می‌شود. سقف محصول معمولاً ۱۰ روز forecast است، اما این کد در عمل تعداد روزهای موجود را کمتر یا مساوی این سقف انتخاب می‌کند.
- `backward_days=7` به معنی **۷ روز حرکت به عقب برای هر روز خروجی** است، نه بازهٔ تعداد روزهای خروجی.
- در روزهایی که خشکی در دامنهٔ محاسبات وجود دارد، RK4 ساعتیِ آگاه از خشکی اجرا و هر ذره‌ای که وارد سلول خشکی یا ناحیه حاشیهٔ آن شود نامعتبر می‌شود؛ رفتار مرزی کاملاً تفکیک‌شده با خطوط ساحلی با وضوح بالاتر نیست.
- در روزهای بدون خشکی در داده، انتگرال‌گیر اصلی `numbacs` استفاده می‌شود. پردازش در مناطق بسیار بزرگ می‌تواند پرهزینه باشد. بافر ۱ درجه به دقت نزدیک لبه کمک می‌کند، اما برای جریان‌های سریع ممکن است کافی نباشد.
- پایداری ۳/۵ روزه فقط روزهای واقعاً واقع‌شده در پنجره تقویمی ±۱/±۲ روز را لحاظ می‌کند؛ روزهای مفقود با روزهای دورتر جایگزین نمی‌شوند. در لبه‌ها، تعداد روزهای مشارکت‌کننده کمتر است.
- داشبورد نیازمند دسترسی مرورگر به CDN کتابخانه Leaflet و تایل‌های OpenStreetMap است. هیچ آفست دستی تصویری اعمال نمی‌شود.
- این تحویل با تست‌های مصنوعی محلی و تست ساخت داشبورد/ویدیو ارزیابی شده؛ **دانلود زنده Copernicus و اجرای واقعی بسته NumbaCS در این محیط قابل انجام نبوده و قبل از بهره‌برداری عملی باید از طریق GitHub Actions تست شوند.**

برای جنوب جاوه می‌توانی preset زمانی `jakarta` (UTC+7) را در فرم GitHub Actions انتخاب کنی. از workflow جداگانه `Estimate Seyd Yar LCS data volume` هم می‌توانی برای تخمین حجم درخواست کامل استفاده کنی.
